# End-to-end verification

## Real detector and local live replay

Command (run from `backend/`):

```bash
RS_RUN_REAL_YOLO_E2E=1 \
RS_TEST_ADMIN_DATABASE_URL=postgresql+psycopg://postgres@127.0.0.1:55438/postgres \
../.venv/bin/python -m pytest tests/test_real_yolo_e2e.py -q -s
```

Latest run: **1 passed** on 2026-11-06 using the official YOLOX-S ONNX weight file and CC BY 3.0
Wikimedia street-traffic recording, served as loopback-only 10 FPS MJPEG replay. It made real HMAC
requests to localhost FastAPI, persisted the scoped camera telemetry in the isolated PostgreSQL
test database, signed in through the MFA flow in Chromium, and rendered the actual camera detail
from `/api/cameras` without API stubs. The browser saw the heartbeat change while inference was
active (2,387 ms observed refresh) and displayed 147 cumulative observations and two crossings.

Persisted telemetry evidence: 65 source frames; 342 tracked observations; 26 tracks (bus 11, car 6,
truck 9); two `midline` crossings by bus; source healthy at 1920×1080, zero reconnects/failures;
CPU pipeline 1.587 FPS; p50/p95/p99 inference 84.49/99.41/103.85 ms; peak RSS 346.8 MB. No real
incident candidate was emitted. Full report:
[YOLO_REAL_INFERENCE_REPORT](YOLO_REAL_INFERENCE_REPORT.md).

The same run submitted a separately marked synthetic candidate through signed HTTP ingestion. The
authenticated browser opened its incident detail, rejected it with an audit note, displayed the
rejected state, and the test asserted the rejected row and `alert.rejected` audit entry in
PostgreSQL. It was not generated by the YOLO replay. Pipeline shutdown stops the loopback relay
before terminating capture so the OpenCV network read can unwind within the bounded cleanup.

The test exercises measured aggregates and model metadata via the existing tenant-scoped camera
heartbeat JSONB contract; it does not save every frame's bbox row in PostgreSQL. Per-frame local
JSONL detections remain opt-in. It does not verify external Romanian LIVE ingestion, ground-truth
precision/recall, count accuracy, incident performance, multi-camera throughput, or encrypted
event evidence because the replay produced no event.


Latest result: **34 passed**. These are synthetic track sequences, including probable-crash,
near-miss, wrong-way and congestion logic. They validate rule implementation against constructed
measurements; they are not real incidents or field accuracy evidence.

`backend/tests/test_ingest_idempotency.py::TestNewRuleTypes::test_synthetic_rule_candidate_ingest_persistence_and_operator_review`.
It drives a deterministic reverse-motion track through the production `RuleEngine` at 25 FPS,
then passes it through the production `AlertGate`, and labels the resulting candidate `SYNTHETIC TEST`. The candidate traverses signed multipart event
ingestion, PostgreSQL, operator detail/reject APIs, the real archive search endpoint, and the
append-only audit assertion. The focused ingestion file passed (**9 tests**) against isolated
PostgreSQL. This proves the generated rule-to-API/database/operator/archive path for a constructed
scenario; it does not establish real-scene rule accuracy or the pipeline's event-evidence/clip
publishing glue. The separate full E2E exercises browser incident review with a signed synthetic event.
