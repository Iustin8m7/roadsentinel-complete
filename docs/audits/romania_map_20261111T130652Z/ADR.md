# ADR: geographic provenance on canonical RoadSentinel incidents

Accepted for implementation after actual code inspection, 2026-11-11. Existing Camera latitude/longitude lack verification/revision evidence and will NOT be promoted/backfilled. Existing maps are schematic camera views; the national map is a protected incident view using the same Alert identities, not another incident system.

Flow: encrypted Recording → existing AnalysisRun/YOLOX-S ONNX/ByteTrack → candidate → explicit offline_promotion → canonical Alert/evidence/casework → geographic source link → RLS-protected map query → authenticated React/Leaflet view/detail.

- Add append-only tenant geo revisions for Recording/Camera/Alert, with exactly one real scoped FK subject, finite coordinates, accuracy/provenance/source references, revisions and explicit state. Unknown has NULL coordinates. Source names/files/pixels/legacy numeric camera columns are never location evidence.
- Add one incident source link keyed by canonical alert UUID. Live events snapshot the geography of their exact acknowledged approved CameraConfigVersion; camera edits cannot move history. Camera pins belong to versioned approved configuration JSON and use the existing independent approval. Workers continue sending IDs/revision, never GPS.
- Recorded alerts derive from their recording's confirmed source revision. Recording source correction is audited and updates derived unreviewed incidents through a DB join, not an unreliable in-memory callback. Confirmed/held case sources cannot be silently changed; incident overrides require a proposal and distinct admin sign-off.
- Incident-specific accepted override outranks confirmed recording assignment, which outranks the immutable camera-version snapshot. Pending/rejected proposals do not replace an accepted point. Camera/video anchors are not exact event positions. Moving/composite source locations cannot pretend to be one precise event coordinate.
- Preserve canonical event idempotency, status, role scope (patrol assigned only), MFA, CSRF, FORCE RLS, encryption, source-rights and export approval. Map summaries expose no media URLs/private body/plates. Audit records revision IDs/reason, not precise coordinate values; protected append-only rows retain full provenance.
- Use existing Leaflet1.9.4; no PostGIS is required for numeric country/bbox queries. Use bounded pagination and a single tenant/role-filtered SQL projection plus exact classified counts. No new definer function or BYPASSRLS role. New tables get composite tenant FKs, FORCE RLS, least grants and immutable-row trigger.
- Ship version-pinned Natural Earth public-domain Romania outline/counties/places and cartographic roads for an actual offline vector basemap. This is cartographic, not cadastral/legal boundary certification. Two-km border band is explicitly uncertain. No network geocoding, device GPS or image geolocation. Local place search supplies unverified candidates requiring confirmation.
- Optional tiles are administrator-configured and off by default. No third-party receives private video/incident payloads. Do not run automated OSM tile scraping/pan tests; its policy prohibits it. Reference data attribution remains visible and map/list survives provider loss.
- Default map excludes explicitly synthetic/demo sources and rejected alerts. Demo inclusion is permission-gated and labelled. Unknown and outside-region counts remain explicit. Capture UTC is nullable; detection/upload time is never asserted as recording time.
- Test a fresh migrated disposable cluster and representative0022→0023 rows before touching any existing integration DB. No native upgrade is automatic. Native upgrade requires exact identity and a verified backup/restore; otherwise ship guarded procedure and mark native map activation blocked.
